## [Unreleased]

### Added (seed an AMI over the admin API, 2026-10-09)
- **`POST /mock/images`** registers one AMI: `{"ami_id", "name", "region", "root_device_name"}`, with `owner_id` (`amazon`), `virtualization_type` (`hvm`) defaulted, and `account_id` optional but only `000000000000`, the one account the EC2 surface reads. It writes through `SeedAMI`, so DescribeImages and RunInstances see it like a fixture; seeding twice is a no-op and `/mock/reset` drops it. An id that is not `ami-` plus hex, a missing region or root device name, another account, an unknown field or trailing data is 400 with nothing written. RunInstances still refuses unseeded ids. `TestAdminMockImages_*` pin it.

### Changed (provider-smoke runs its examples in parallel, 2026-09-29)
- **The smoke harness runs every example at once** (`t.Parallel`, CI `-parallel 64`) against one fakeaws, reset once at the start instead of before each example. Each tofu call starts the provider about three times, so one 4-vCPU runner stays CPU-bound for over 5 minutes: CI deals the sorted examples round-robin across five `provider-smoke (i/5)` runners with `SMOKE_SHARD=i/5`, and the `provider-smoke` job now only checks that every shard passed. `TF_PLUGIN_CACHE_MAY_BREAK_DEPENDENCY_LOCK_FILE` stops each init re-downloading the provider under the cache lock. `TestSmokeEnvFailsClosed` and `TestWebStepOneState` drive a temp copy of their example so they run alongside it. `TestExampleResourceNamesAreUnique` fails when two examples name the same queue, role, table, zone, identifier or key pair; `update_tags_every_service` and `update_default_tags` are renamed off `tags_every_service`'s names.
- **DescribeVpcs honours `VpcId.N` and DescribeInternetGateways `InternetGatewayId.N`**, answering 400 `InvalidVpcID.NotFound` / `InvalidInternetGatewayID.NotFound` for a missing one. They listed every VPC or gateway in the region, so the provider's lookup by id found "too many" once two examples had a VPC. `TestEC2_DescribeVpcsAndIGWsByID` pins it.
- **SetQueueAttributes stores the attributes** it is given; it answered 200 and dropped them, so the provider's propagation wait on `aws_sqs_queue` updates ran out its 3 minutes. `updates/update_sqs_queue_visibility` leaves knownRed. `TestSQS_SetQueueAttributesReadsBack` pins it.

### Fixed (DeleteKeyPair by KeyPairId, 2026-09-29)
- **DeleteKeyPair takes `KeyPairId`**, as EC2 does: the `key-...` id DescribeKeyPairs lists and the AWS scope reap deletes by. It read only `KeyName`, so a delete by id answered 404 and left the key pair. `TestEC2_DeleteKeyPairByID` pins it.

### Added (the EC2 Describes the AWS scope sweep calls, 2026-09-28)
- **An unfiltered DescribeAddresses lists every Elastic IP in the region**; it described nothing without `AllocationId.N`. DescribeAddressesAttribute does the same.
- **An unfiltered DescribeSecurityGroups lists every group in the region**; it answered 409.
- **DescribeImages honours `Owner.N`**, with `self` meaning the caller, so `Owner.1=self` returns none of the fixtures; it ignored the owner and returned them all. `IncludeDisabled=true` is accepted and changes nothing, since no image is disabled. `ImageId.N` lookups are unchanged.
- **DescribeVolumes, DescribeNatGateways, DescribeSnapshots and DescribeLaunchTemplates** answer their real result, an empty `volumeSet` / `natGatewaySet` / `snapshotSet` / `launchTemplates`, since fakeaws creates none of them. They were 404.
- Each of these refuses a param it does not model with 409 instead of ignoring it: `Filter.N` everywhere, plus `PublicIp.N` on DescribeAddresses and `GroupName.N` on DescribeSecurityGroups.
- The unfiltered DescribeNetworkInterfaces already omits a terminated instance's ENI; `TestRegressionSweepTerminatedInstanceENIGone` pins it.
- The tests drive these through `aws-sdk-go-v2` (a new test dependency). `coverage_matrix.yaml` gains `aws_ami`, `aws_network_interface`, `aws_ebs_volume`, `aws_nat_gateway`, `aws_ebs_snapshot` and `aws_launch_template` rows, and the `aws_eip` and `aws_security_group` rows name their sweep tests.

### Fixed (instance profile roles, Aurora clusters, cluster parameter groups and EIPs converge, 2026-09-28)
- **An instance profile's role reads back.** A role in a list was marshalled as `<Role>`, not `<member>`, so GetInstanceProfile looked roleless: the next plan showed `+ role` and its apply failed AddRoleToInstanceProfile 409. The role and instance profile shapes lose their `XMLName` and CreateRole/GetRole/CreateInstanceProfile/GetInstanceProfile wrap them instead, which also fixes ListRoles and ListInstanceProfiles.
- **`aws_rds_cluster` stops planning a replacement.** DescribeDBClusters returns `EngineMode` (`provisioned` unless CreateDBCluster sent one), and echoes the `Port`, `BackupRetentionPeriod`, `PreferredBackupWindow`, `PreferredMaintenanceWindow`, `DatabaseName`, `StorageEncrypted`, `CopyTagsToSnapshot`, `IAMDatabaseAuthenticationEnabled`, `AvailabilityZones` and `VpcSecurityGroups` CreateDBCluster was given, with RDS's defaults for the unset ones (port 3306 for MySQL engines, else 5432; retention 1), plus `Endpoint`/`ReaderEndpoint`. DescribeGlobalClusters answers an empty list. DeleteDBCluster returns the cluster in `deleting` state, and a missing cluster answers 404 `DBClusterNotFoundFault`.
- **`aws_rds_cluster_parameter_group` applies.** DescribeDBClusterParameters answers an empty list, as DescribeDBParameters does (404 `DBParameterGroupNotFound` for a missing group). DeleteDBClusterParameterGroup answers 400 `InvalidDBParameterGroupState` for a group a cluster uses and 404 `DBParameterGroupNotFound` for a missing one.
- **`aws_eip` applies.** DescribeAddressesAttribute answers each allocation without a `ptrRecord`. DescribeAddresses and DescribeAddressesAttribute answer a missing allocation 400 `InvalidAllocationID.NotFound`.
- **Tags round-trip on Aurora clusters, cluster parameter groups and EIPs**: `Tags.Tag.N` on CreateDBCluster/CreateDBClusterParameterGroup and `TagSpecification.N` of type `elastic-ip` on AllocateAddress are stored; the RDS tag calls take `cluster` and `cluster-pg` ARNs, and CreateTags/DeleteTags an `eipalloc-` id. DescribeDBClusters returns `TagList` and DescribeAddresses `tagSet`. Tags go with their resource.
- New `examples/updates/update_default_tags` (a cluster, its parameter group and an EIP, with a resource tag and a provider `default_tags` value changing v1→v2); `coverage_matrix.yaml` names it for the three instead of `updates_exempt`. `update_tags_every_service`'s instance profile now has a role.

### Added (tags on the rest of the taggable resources, 2026-09-28)

Create-time tags (`tags` on CreateNodegroup/CreateAddon, `Tags.member.N` on CreateInstanceProfile, `TagSpecification.N` of type `key-pair` on ImportKeyPair) come back from DescribeNodegroup/DescribeAddon `tags`, GetInstanceProfile `Tags` and DescribeKeyPairs `tagSet`. ### Fixed (Secrets Manager tag mutations, 2026-09-28)
- **Secrets Manager TagResource and UntagResource persist.** Both were stubs that answered 200 and dropped the change, so a secret kept its create-time tags forever and a changed tag (a new provider `default_tags` value) showed as drift on every later plan. TagResource adds or overwrites the keys it names, UntagResource removes them, and DescribeSecret returns the result. A missing secret answers 404 `ResourceNotFoundException`.

### Added (tags on SQS, IAM, RDS, Route53, DynamoDB and EKS, 2026-09-28)
- **Tags round-trip on SQS queues, IAM roles/users/policies, RDS instances/parameter groups/subnet groups, Route53 hosted zones, DynamoDB tables and EKS clusters.** Create-time tags are stored (`tags` on CreateQueue, `Tags.member.N` on CreateRole/CreateUser/CreatePolicy, `Tags.Tag.N` on CreateDBInstance/CreateDBParameterGroup/CreateDBSubnetGroup, `Tags` on CreateTable, `tags` on CreateCluster) and come back exactly, empty values and keys with `:` or `/` included, from ListQueueTags, List{Role,User,Policy}Tags and Get{Role,User,Policy}, RDS ListTagsForResource and DescribeDBInstances `TagList`, Route53 ListTagsForResource, ListTagsOfResource, and DescribeCluster `tags` / EKS ListTagsForResource.
- **The tag mutations land**: TagQueue/UntagQueue, Tag/Untag{Role,User,Policy}, AddTagsToResource/RemoveTagsFromResource, ChangeTagsForResource (adds and removes in one transaction), and DynamoDB and EKS TagResource/UntagResource. Each changes only the keys it names. The SQS, RDS and Route53 tag calls were stubs that accepted and dropped tags, and listed none.
- **An unknown resource answers with the service's not-found shape**: SQS 400 `AWS.SimpleQueueService.NonExistentQueue`, IAM 404 `NoSuchEntity`, RDS 404 `DBInstanceNotFound` / `DBParameterGroupNotFound` / `DBSubnetGroupNotFoundFault`, Route53 404 `NoSuchHostedZone`, DynamoDB 400 `ResourceNotFoundException`, EKS 404 `NotFoundException`. An RDS ARN of another resource type answers 400 `InvalidParameterValue`, and a Route53 resource type other than `hostedzone` 400 `InvalidInput`.
- New `repository/tags.go` table `resource_tags`, keyed by ARN and in the reset tables. A trigger on each taggable table drops a resource's tags with its row, so a resource recreated under the same ARN starts untagged. The RDS instance's unread `tags` JSON field is gone.
- New `examples/working/tags_every_service` (provider `default_tags` plus one tagged resource per service) and `examples/updates/update_tags_every_service` (v1→v2 changes, removes and adds a tag). `coverage_matrix.yaml`'s `aws_dynamodb_table`, `aws_eks_cluster` and `aws_route53_zone` rows name the latter instead of `updates_exempt`.

### Added (EC2 tags, 2026-09-28)
- **Tags round-trip on VPCs, subnets, internet gateways, route tables, security groups and instances.** `TagSpecification.N` is stored on CreateVpc, CreateSubnet, CreateInternetGateway, CreateRouteTable, CreateSecurityGroup and RunInstances (`instance` and `network-interface`; the `volume` spec the provider adds with `default_tags` is accepted and dropped, as fakeaws has no volumes). A spec for any other resource type answers 400 `InvalidParameterValue` and creates nothing. Each Describe* returns the resource's tags as `tagSet`.

### Changed (security-group rule validation, 2026-09-28)
- **AuthorizeSecurityGroup{Ingress,Egress} refuse malformed permissions** with 400 `InvalidParameterValue` and real EC2's message for the case: a bad IPv4 or IPv6 CIDR (`CIDR block <x> is malformed`), a tcp/udp port outside 0-65535 (`TCP/UDP (to) port (70000) out of range`), an ICMP/ICMPv6 type or code outside -1..255 (`ICMP type (256) out of range`) or type -1 with a code other than -1 (fakeaws's own wording, as AWS documents the rule but not a message), or a protocol other than tcp, udp, icmp, icmpv6, -1 or 0-255 (`Invalid value 'bogus' for IP protocol. Unknown protocol.`). A literal `all` is refused the same way, as EC2 does; the provider sends `-1` for it. Protocols 6/17/1/58 get the same port checks as their names. FromPort > ToPort for tcp/udp answers `Invalid port range 80-70 for protocol 'tcp': ...`; AWS documents no message for it, so that wording is fakeaws's own. Nothing is stored on a refusal.
- **A same-account `Groups.N.GroupId` that names no security group** answers 400 `InvalidGroup.NotFound`. A pair carrying another account's `UserId` is admitted unchecked.
- New `examples/misconfigured/sg_ingress_inverted_port_range`, `sg_ingress_port_out_of_range` and `sg_ingress_unknown_protocol` (each `expected.txt` pins `<code>: <message prefix>`), and `examples/working/security_group_edge_rules` (all protocols to 0.0.0.0/0, tcp 0-65535, icmp -1/-1).

### Added (SSM Parameter Store, 2026-09-28)
- **SSM lands** (`handlers/ssm.go`, JSON 1.1 `X-Amz-Target: AmazonSSM.*` at `POST /ssm/region/<region>`): `PutParameter`, `GetParameter`, `DescribeParameters` (`Name` `Equals` filters or none, one page), `DeleteParameter`, and `ListTagsForResource` / `AddTagsToResource` / `RemoveTagsFromResource` on `ResourceType=Parameter` (unknown parameter: 400 `InvalidResourceId`), which is what `aws_ssm_parameter` and `data.aws_ssm_parameter` call at hashicorp/aws 5.100.0. Missing parameters are 400 `ParameterNotFound` on Get and Delete. GetParameter and the tag operations also take the parameter's ARN (matched against its own region and account), as the provider passes after an import by ARN. Names prefixed `aws`/`ssm`, unknown types, and tags with overwrite are 400 `ValidationException`. `TestContract_ssm_put_parameter_no_overwrite_cas` pins the contract.

### Added (instance primary ENIs with private and public IPs, 2026-09-28)
- **RunInstances accepts `NetworkInterface.1.*`.** `DeviceIndex`, `SubnetId`, `SecurityGroupId.N`, `AssociatePublicIpAddress` and `DeleteOnTermination` launch an instance with no top-level `SubnetId` (409 before); the provider uses this form whenever `associate_public_ip_address` is set. Both forms run the same subnet lookup and SG-VPC check, so they fail with the same error. `SubnetId`, `SecurityGroupId.N` or `PrivateIpAddress` next to `NetworkInterface.1.*` is `InvalidParameterCombination` (400). A second interface, an existing `NetworkInterfaceId` or `DeleteOnTermination=false` is refused (409).
- **Each instance gets a primary ENI** (new `ec2_network_interfaces` table, reset with the rest) holding the requested private IP (`PrivateIpAddress` or `NetworkInterface.1.PrivateIpAddress`; 409 if it is taken, reserved or outside the subnet) or else the lowest free one in the subnet CIDR (AWS's first four and last addresses skipped; a full subnet is 409), `sourceDestCheck` true, the security groups, and a public IP (203.0.113.0/24) only with `AssociatePublicIpAddress=true`. The instance and its ENI are inserted in one transaction.
- **DescribeInstances** gains `privateIpAddress`, `ipAddress`, `sourceDestCheck` and `networkInterfaceSet`, and `groupSet` is the ENI's groups. `ipAddress` and the ENI's `association` appear only with a public IP, because the provider reads `associate_public_ip_address` (ForceNew) as `association != nil` (`CRITICAL[ec2-instance-public-ip-from-primary-eni]`).
- **DescribeNetworkInterfaces** returns the ENIs (was always empty), by `NetworkInterfaceId.N` (unknown id: `InvalidNetworkInterfaceID.NotFound`) and filters `network-interface-id`, `attachment.instance-id`, `subnet-id` and `group-id`; any other filter is refused (409) rather than ignored.
- **ModifyNetworkInterfaceAttribute** `SecurityGroupId.N` replaces the ENI's groups, and so the instance's `groupSet`, after the same SG-VPC check. It is where the provider sends `vpc_security_group_ids` changes. Other attributes are refused (409).
- **ModifyInstanceAttribute `SourceDestCheck.Value`** is stored on the primary ENI, so `source_dest_check = false` reads back; other attributes stay accepted and unstored.
- **TerminateInstances deletes the ENI.** A terminated instance has no network fields.
- **`/mock/state`** gains `ec2.network_interfaces[]` (`id`, `instance_id`, `subnet_id`, `vpc_id`, `private_ip`, `public_ip`, `security_group_ids`, `source_dest_check`, `region`), and each `ec2.instances[]` entry gains `public_ip` and `private_ip`; its `vpc_security_group_ids` now come from the ENI and are `[]`, not null, when empty.
- **DescribeInstanceAttribute `userData`** is an empty `<userData/>`, as AWS answers for an instance without user data; the `<value></value>` it returned read back as `user_data = sha1("")` and planned a diff. `working/basic_instance` passes and leaves knownRed.
- New `examples/working/instance_public_ip` (`associate_public_ip_address = true`, two SGs, provider 5.100.0).

### Changed (security group rules keep the whole ip_permissions shape, 2026-09-28)
- **Every rule source round-trips.** `AuthorizeSecurityGroup{Ingress,Egress}` and the matching Revokes now parse `IpRanges` (`CidrIp`, `Description`), `Ipv6Ranges`, `Groups` (UserIdGroupPairs: `GroupId`, `UserId`, `Description`) and `PrefixListIds`; before, only IPv4 CIDRs survived, so an inline `ipv6_cidr_blocks` or `security_groups` rule planned a diff after every apply. `DescribeSecurityGroups` echoes each source on its own item with its description (`CRITICAL[ec2-sg-rule-source-descriptions-round-trip]`).
- **Rules are per source, as in AWS.** Authorize adds a source to the permission with the same protocol and ports; Revoke removes only the named sources (revoking `::/0` keeps `0.0.0.0/0` on the same port) and drops a permission once it has none left.
- **`/mock/state` exports rules.** Each `ec2.security_groups[]` entry gains `ip_permissions` and `ip_permissions_egress`: `from_port`, `to_port`, `ip_protocol`, `ip_ranges[{cidr_ip, description}]`, `ipv6_ranges[{cidr_ipv6, description}]`, `user_id_group_pairs[{group_id, user_id, description}]`, `prefix_list_ids[{prefix_list_id, description}]`. Every key is always present and lists are never null. Pinned by `TestEC2_SecurityGroupStateRulesGolden`.
- New `examples/working/security_group_full_shape` (IPv6 ingress, SG-to-SG rule, allow-all egress; provider pinned to 5.100.0).
