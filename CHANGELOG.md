## [Unreleased]

### Added (request-log read-set fields, 2026-10-12)
- **Every request-log entry carries ADR-0041's read-set fields `{service, protocol, action, params}`** beside `{method, path, status, classification}`. `serviceProtocols` in `handlers/recorder.go` gives each landed service its protocol; a `query` entry's `action` is the form body's `Action` and its `params` every other field but `Version`, a `json` entry's `action` is the operation after the dot in `X-Amz-Target` and its `params` the body's JSON object, and a `rest` entry's `action` is `"<METHOD> <route pattern>"` (the route chi matched, trailing slash kept) and its `params` `{path, query}`, so `GetBucketTagging` and `GetBucketPolicy` on one bucket are two entries. A body that does not parse, a query body that repeats a key or a json body that is not an object records `null` params; a path no landed service owns records an empty `service`, `protocol` and `action`.
- **The recorder reads only a query or json body** and puts back a reader of the same bytes, then the same read error, so every handler answers as before; it never reads a rest body, so an S3 upload is not buffered.
- **`/mock/state`'s `audit` now fills `protocol` and `action`**; params stay in process memory, in `GET /mock/requests` only, never the db, the snapshot or `/mock/state`. `TestContract_request_log_read_set_entry`, `TestRequestLog_RESTEntries`, `TestRequestLog_BodyRestored`, `TestRequestLog_ParamsStayInMemory` and `TestRequestLog_EveryLandedServiceHasAProtocol` pin it; `TestContract_state_audit_no_values` now expects the filled fields.

### Added (request-log gap marks, 2026-10-12)
- **The request log tells three gaps apart from answers read from rows**, with every wire byte unchanged. The default arm of EC2, IAM, RDS, DynamoDB, SQS, Secrets Manager and KMS records `not-modelled-404`; its 404 `ResourceNotFoundException` is wire-identical to a missing row's, which stays `answered-from-rows`. EC2's refused filters (`refuseUnmodelled` and the `DescribeRouteTables`, `DescribeAddresses`, `DescribeNetworkInterfaces` and `DescribeTags` filter checks), `AllocateAddress` `Domain` other than `vpc`, `AssociateAddress` `AllowReassociation=true`, `RunInstances` on a network interface fakeaws does not launch, `ModifyNetworkInterfaceAttribute` without `SecurityGroupId.N`, and the required-parameter checks stricter than EC2's (`CreateVpc` `CidrBlock`, `CreateSubnet` `CidrBlock`, `AssociateRouteTable` `SubnetId`, `CreateRoute` `DestinationCidrBlock`, `CreateSecurityGroup` `VpcId`, `GroupId` on `DeleteSecurityGroup` and on the `Authorize`/`Revoke` rule calls, `AuthorizeSecurityGroup*` `IpPermissions`, `RunInstances` `SubnetId`/`InstanceType`) (still 409); `RunInstances` `TagSpecification` resource types fakeaws does not tag (EC2 also tags `spot-instances-request` and others there; on the other creates a refused type is one EC2 refuses too, so it stays `answered-from-rows`), `CreateTags`/`DeleteTags` ids of a type fakeaws does not tag, and RDS and Route53 tag calls on a resource type fakeaws does not tag (still 400); and SSM's `DescribeParameters` `Filters` and non-`Name` `ParameterFilters`, and SSM `ListTagsForResource`, `AddTagsToResource` and `RemoveTagsFromResource` on a `ResourceType` other than `Parameter` (still 501) record `filter-refused`; a modelled 409 stays `answered-from-rows`. Only `DescribeVolumes`, `DescribeNatGateways`, `DescribeSnapshots` and `DescribeLaunchTemplates` (`ec2DescribeNone`) record `empty-collection`. concepts.md item 7 states which gaps are never marked, with examples, and they still record `answered-from-rows`. `TestContract_request_log_not_modelled_404`, `TestContract_request_log_filter_refused` and `TestContract_request_log_empty_collection` pin it.

### Changed (every service answers the stored account, 2026-10-12)
- **SSM, KMS, DynamoDB, Secrets Manager, SQS, EKS, RDS, Route53 and S3 read `Application.AccountID()` instead of `000000000000`**, once at each handler's entry. Their ARNs and row keys, the SQS queue URL, and the S3 `ListBuckets` owner id carry the stored account. A KMS key carries the account it was created under, in its ARN, `AWSAccountId` and default key policy's `arn:aws:iam::<account>:root` principal, even after an identity change (keys stay in the in-memory `kmsStore`); `GetKeyPolicy` for an unknown KeyId names the stored account. So under another account RDS `CreateDBSubnetGroup` finds EC2 subnets, and EKS `CreateCluster` and `CreateNodegroup` find EC2 subnets, security groups and IAM roles, created through the API. Route53 zones and S3 buckets stored under another account are not listed. An unreadable identity is 500 in each service's error shape, never the default. AWS public SSM parameters keep their empty account.
- **`/mock/state` reads the account once and passes it to every gather**, so no gather reads it a second time.
- **An identity change cannot land inside an AWS request.** Every AWS request, `POST /mock/images` and `GET /mock/state` (both routes) hold `Application.identityMu` shared for the whole request; `POST /mock/identity` (and `-account` at boot), `/mock/reset`, `/mock/restore` and `/mock/snapshot` hold it exclusively. So a create cannot read the old account, lose the race to an identity change, reset or restore, and then write a row under an account `AccountID()` no longer returns; `/mock/state` never reads the db handle a restore is replacing, nor stamps an account whose rows a reset removed; and a snapshot never catches half a request's writes or runs on a handle a restore closes.
- `TestStoredAccount_ServiceARNs`, `TestStoredAccount_ZonesAndBucketsListed`, `TestStoredAccount_UnreadableIdentityIs500`, `TestSetIdentity_RacesCreate`, `TestMockReset_RacesCreate`, `TestMockRestore_RacesStateAndSnapshot`, `TestKMS_KeyKeepsItsAccount` and `TestAccountSourceScan` pin it. The scan fails when a non-test `handlers` file other than `awsproto/awsproto.go` holds the literal `000000000000`, or when anything but `AccountID` and `setIdentity` in `admin.go` names `FakeAccountID`.

### Changed (EC2 answers the stored account, 2026-10-11)
- **EC2 reads `Application.AccountID()` instead of `000000000000`.** Every EC2 row key and ARN, every `ownerId` (VPC, subnet, internet gateway, route table, security group, reservation, ENI), the ENI attachment's `instanceOwnerId`, the instance's `iamInstanceProfile` Arn and the ec2 block of `/mock/state` use the stored account, so RunInstances finds the boot AMI fixtures and IAM instance profiles created through IAM under it, and the lazy AMI seed of a region outside the boot list seeds under it. An unreadable identity is 500 `InternalFailure` on every EC2 action, never the default. With no identity stored EC2 answers `000000000000` as before. The other services still look up the EC2 and IAM rows they reference under `000000000000`, so under another account, until they move: `CreateDBSubnetGroup` does not find EC2 subnets, which it did before this change while EC2 used `000000000000` too; EKS `CreateCluster` does not find EC2 subnets or security groups; and EKS `CreateCluster` and `CreateNodegroup` do not find IAM roles. `TestEC2_AnswersStoredAccount`, `TestEC2_LazySeedUnderStoredAccount` and `TestEC2_UnreadableIdentityIs500` pin it.

### Added (-record-requests: an in-memory request log, 2026-10-11)
- **`-record-requests` (`Options.RecordRequests`) logs every request outside `/mock` and `/healthz`** as `{method, path, status, classification}` in completion order, returned by `GET /mock/requests` and emptied by `POST /mock/requests/clear`. `handlers.NewApplication` refuses `RecordRequests` without an `AdminToken` (`ErrRecordRequestsNeedsAdminToken`), since paths hold values, so fakeaws refuses to start with it and no `-admin-token` or `FAKEAWS_ADMIN_TOKEN`. Off by default: nothing is recorded, `/mock/state`'s `audit` stays `[]` and both routes are the router's 501, as before.
- **Classification**: the last class a site marks wins, so a class does not come from the status; unmarked, a 5xx is `unimplemented-501` and anything else `answered-from-rows`. The router's NotFound and MethodNotAllowed, `writeUnimplemented` (STS AssumeRole, unknown SSM targets) record `unimplemented-501`. The recorder runs inside Recoverer, so a handler that panics records 500 `unimplemented-501` even when it wrote 200 first.
- **Storage**: a mutex-guarded slice, never the database or the snapshot. `/mock/reset` clears it, `/mock/snapshot` and `/mock/restore` leave it, a restart empties it.
- **`/mock/state`'s `audit` is the log as `{service, protocol, action, status, class}`**, never a path or value: `service` is a `LandedServices` id or empty; `protocol` and `action` are empty for now. `TestContract_request_log_needs_admin_token`, `TestContract_request_log_off_by_default`, `TestContract_request_log_unimplemented_501`, `TestContract_request_log_panic_recorded`, `TestContract_state_audit_no_values`, `TestRequestLog_*` and `TestRecordRequestsNeedsAToken` pin it.

### Changed (IAM and STS answer the stored account, 2026-10-11)
- **IAM and STS read `Application.AccountID()` instead of `000000000000`.** Every IAM ARN and row key, and the IAM block of `/mock/state`, use the stored account; `GetCallerIdentity` answers it as `Account` and in `Arn` (`arn:aws:iam::<account>:user/fakeaws`). An unreadable identity is 500 `InternalFailure` on every IAM action and on `GetCallerIdentity`, never the default, and writes nothing. With no identity stored both answer `000000000000` as before. EC2 and the other services still answer as `000000000000`, so under another account EC2 and EKS do not find IAM instance profiles and roles created through IAM until they move too. `TestIAM_ARNsCarryStoredAccount`, `TestIAM_UnreadableIdentityIs500`, `TestSTS_CallerIdentityAnswersStoredAccount` and `TestSTS_UnreadableIdentityIs500` pin it.

### Added (stored identity: -account, -region and POST /mock/identity, 2026-10-11)
- **A one-row `identity` table holds the account id and region**, set by `-account` (12 digits) with `-region` (needs `-account`) at boot or by `POST /mock/identity` `{"account_id", "region"}`. A different account on a database holding any row outside `repository/identity.go`'s `emptyExclusions` (operations, audit, the identity, the fixture AMIs) is refused naming both ids: 409, or a failed boot. `/mock/images` rows count; KMS keys, which are not rows, do not. Snapshot, restore and restart keep the identity; `/mock/reset` deletes it, back to `000000000000`. `Application.AccountID()` reads it on every call, and an unreadable identity is 500 on `/mock/identity`, `/mock/images` and `/mock/state`. The boot AMI fixtures and `/mock/images` go under the stored account; IAM, STS and EC2 still answer as `000000000000`, so for now RunInstances does not see those images under another account. With no flag nothing is written and nothing changes. `TestContract_identity_change_refused_on_non_empty_db`, `TestContract_identity_stored_in_database` and `TestAdminMockIdentity_*` pin it.

### Changed (files fakeaws creates are 0600, 2026-10-11)
- **A file-backed db is owner-only.** With `-db <file>`, a db fakeaws creates is created 0600 before SQLite opens it, so its `-wal`/`-shm` (which SQLite gives the db's mode) are 0600 too; `/mock/snapshot` creates `<db>.snapshot.tmp` 0600, has `VACUUM INTO` fill it and renames it to `<db>.snapshot`; and `/mock/restore` recreates a removed live db 0600. All were 0644 under umask 022. A db that already exists keeps its mode; `:memory:` is unchanged.
- **A failed or killed snapshot leaves no `.snapshot`**, so the next `/mock/restore` is 404 instead of copying an empty or partial file over the live db. A `.snapshot.tmp` a killed snapshot left is replaced by the next one. `TestContract_file_backed_db_owner_only` and `TestAdminMockSnapshot_FailedVacuumLeavesNoSnapshot` pin both bullets; `TestAdminMockRestore_MemoryConflict` pins that `:memory:` restore is still 409.

### Added (-bind, -admin-token and a loopback-Origin guard on /mock, 2026-10-11)
- **`-bind <host>`** sets the listen host; empty keeps `:<port>` on all interfaces. `Options.ListenAddr()` joins host and port, so `-bind ::1` listens on `[::1]:<port>`.
- **`-admin-token <token>`, else `FAKEAWS_ADMIN_TOKEN`**, gates every `/mock` path, unknown ones included: a present `Origin` that is not loopback (`localhost` or a loopback IP literal; `null` and lookalikes such as `http://localhost.evil` refused) is 403, then anything but `Authorization: Bearer <token>` is 401. Neither body names the token, and the startup log says only whether one is set. `/healthz` and the AWS surface are not gated; without a token `/mock` answers exactly as before.
- **`handlers.NewApplication` takes `handlers.Options{DBPath, Echo, Bind, Port, AdminToken}`** instead of `(dbPath, echo)`. `TestContract_listen_addr_default_all_interfaces`, `TestContract_mock_admin_token_required`, `TestContract_mock_admin_origin_loopback_only` and `TestAdminMock_NoTokenIsUngated` pin it.

### Fixed (region endpoints accept a trailing slash, 2026-10-11)
- **`POST /<service>/region/<region>/` routes like the slash-less endpoint.** smithy-go 1.28.2 keeps a trailing slash when it joins a path-style `BaseEndpoint` with an operation path of `/`, so aws-sdk-go-v2 clients pointed at e.g. `/ssm/region/us-east-1` now post to `/ssm/region/us-east-1/`, which was 501. Only the region root is normalised; S3 paths keep their trailing slash. `TestSSM_RegionRootTrailingSlashRoutes` pins it.

### Added (AssociateAddress and DisassociateAddress, 2026-10-10)
- **An `aws_eip` that sets `instance` applies and destroys.** AssociateAddress takes `AllocationId` with `InstanceId` (the instance's primary ENI) or `NetworkInterfaceId`, stores the association on the address and returns its `eipassoc-` id; DescribeAddresses returns `associationId`, `instanceId`, `networkInterfaceId` and `privateIpAddress`, and honours the `association-id` filter the provider reads it back by. While associated the address is the ENI's public IP, so DescribeInstances shows it; DisassociateAddress clears the association and gives the ENI back the public IP its launch assigned, if any. Both were 404. Errors are EC2's: `InvalidAllocationID.NotFound`, `InvalidInstanceID.NotFound`, `InvalidNetworkInterfaceID.NotFound`, `InvalidAssociationID.NotFound`, and `Resource.AlreadyAssociated` for an address or ENI that already has an association; `AllowReassociation=true` is refused 409 as unmodelled. Terminating an instance disassociates its addresses.
- **ReleaseAddress answers as EC2 does**: 400 `InvalidIPAddress.InUse` for an associated address and 400 `InvalidAllocationID.NotFound` for a missing one (was a generic 404).
- New `examples/working/eip_instance` (the step-one web stack plus an attached EIP); `coverage_matrix.yaml` names it for `aws_eip` instead of `working_exempt`. `TestRegressionEIPAssociateWithInstance` and `TestRegressionEIPDisassociatedOnTerminate` pin it.

### Added (seed an AMI over the admin API, 2026-10-09)
- **`POST /mock/images`** registers one AMI: `{"ami_id", "name", "region", "root_device_name"}`, with `owner_id` (`amazon`), `virtualization_type` (`hvm`) defaulted, and `account_id` optional but only `000000000000`, the one account the EC2 surface reads. It writes through `SeedAMI`, so DescribeImages and RunInstances see it like a fixture; `/mock/reset` drops it. Re-seeding an id that already exists in the region, a fixture included, is 200 returning the stored row when every field matches and 409 naming the differing fields otherwise. An id that is not `ami-` plus 8 or 17 lowercase hex digits, a region not shaped like `us-east-1`, a missing name or root device name, another account, an unknown field, trailing data or a body over 64 KiB is 400 with nothing written. RunInstances still refuses unseeded ids. `TestAdminMockImages_*` pin it.

### Changed (provider-smoke runs its examples in parallel, 2026-09-29)
- **The smoke harness runs every example at once** (`t.Parallel`, CI `-parallel 64`) against one fakeaws, reset once at the start instead of before each example. Each tofu call starts the provider about three times, so one 4-vCPU runner stays CPU-bound for over 5 minutes: CI deals the sorted examples round-robin across five `provider-smoke (i/5)` runners with `SMOKE_SHARD=i/5`, and the `provider-smoke` job now only checks that every shard passed. `TF_PLUGIN_CACHE_MAY_BREAK_DEPENDENCY_LOCK_FILE` stops each init re-downloading the provider under the cache lock. `TestSmokeEnvFailsClosed` and `TestWebStepOneState` drive a temp copy of their example so they run alongside it. `TestExampleResourceNamesAreUnique` fails when two examples name the same queue, role, table, zone, identifier or key pair; `update_tags_every_service` and `update_default_tags` are renamed off `tags_every_service`'s names.
- **DescribeVpcs honours `VpcId.N` and DescribeInternetGateways `InternetGatewayId.N`**, answering 400 `InvalidVpcID.NotFound` / `InvalidInternetGatewayID.NotFound` for a missing one. They listed every VPC or gateway in the region, so the provider's lookup by id found "too many" once two examples had a VPC. `TestEC2_DescribeVpcsAndIGWsByID` pins it.
- **SetQueueAttributes stores the attributes** it is given; it answered 200 and dropped them, so the provider's propagation wait on `aws_sqs_queue` updates ran out its 3 minutes. `updates/update_sqs_queue_visibility` leaves knownRed. `TestSQS_SetQueueAttributesReadsBack` pins it.

### Fixed (instance profile roles, Aurora clusters, cluster parameter groups and EIPs converge, 2026-09-28)
- **An instance profile's role reads back.** A role in a list was marshalled as `<Role>`, not `<member>`, so GetInstanceProfile looked roleless: the next plan showed `+ role` and its apply failed AddRoleToInstanceProfile 409. The role and instance profile shapes lose their `XMLName` and CreateRole/GetRole/CreateInstanceProfile/GetInstanceProfile wrap them instead, which also fixes ListRoles and ListInstanceProfiles.
- **`aws_rds_cluster` stops planning a replacement.** DescribeDBClusters returns `EngineMode` (`provisioned` unless CreateDBCluster sent one), and echoes the `Port`, `BackupRetentionPeriod`, `PreferredBackupWindow`, `PreferredMaintenanceWindow`, `DatabaseName`, `StorageEncrypted`, `CopyTagsToSnapshot`, `IAMDatabaseAuthenticationEnabled`, `AvailabilityZones` and `VpcSecurityGroups` CreateDBCluster was given, with RDS's defaults for the unset ones (port 3306 for MySQL engines, else 5432; retention 1), plus `Endpoint`/`ReaderEndpoint`. DescribeGlobalClusters answers an empty list. DeleteDBCluster returns the cluster in `deleting` state, and a missing cluster answers 404 `DBClusterNotFoundFault`.
- **`aws_rds_cluster_parameter_group` applies.** DescribeDBClusterParameters answers an empty list, as DescribeDBParameters does (404 `DBParameterGroupNotFound` for a missing group). DeleteDBClusterParameterGroup answers 400 `InvalidDBParameterGroupState` for a group a cluster uses and 404 `DBParameterGroupNotFound` for a missing one.
- **`aws_eip` applies.** DescribeAddressesAttribute answers each allocation without a `ptrRecord`. DescribeAddresses and DescribeAddressesAttribute answer a missing allocation 400 `InvalidAllocationID.NotFound`.
- **Tags round-trip on Aurora clusters, cluster parameter groups and EIPs**: `Tags.Tag.N` on CreateDBCluster/CreateDBClusterParameterGroup and `TagSpecification.N` of type `elastic-ip` on AllocateAddress are stored; the RDS tag calls take `cluster` and `cluster-pg` ARNs, and CreateTags/DeleteTags an `eipalloc-` id. - New `examples/updates/update_default_tags` (a cluster, its parameter group and an EIP, with a resource tag and a provider `default_tags` value changing v1→v2); `coverage_matrix.yaml` names it for the three instead of `updates_exempt`. `update_tags_every_service`'s instance profile now has a role.

### Fixed (Secrets Manager tag mutations, 2026-09-28)
- **Secrets Manager TagResource and UntagResource persist.** Both were stubs that answered 200 and dropped the change, so a secret kept its create-time tags forever and a changed tag (a new provider `default_tags` value) showed as drift on every later plan. TagResource adds or overwrites the keys it names, UntagResource removes them, and DescribeSecret returns the result. A missing secret answers 404 `ResourceNotFoundException`.

### Added (tags on SQS, IAM, RDS, Route53, DynamoDB and EKS, 2026-09-28)
- **Tags round-trip on SQS queues, IAM roles/users/policies, RDS instances/parameter groups/subnet groups, Route53 hosted zones, DynamoDB tables and EKS clusters.** Create-time tags are stored (`tags` on CreateQueue, `Tags.member.N` on CreateRole/CreateUser/CreatePolicy, `Tags.Tag.N` on CreateDBInstance/CreateDBParameterGroup/CreateDBSubnetGroup, `Tags` on CreateTable, `tags` on CreateCluster) and come back exactly, empty values and keys with `:` or `/` included, from ListQueueTags, List{Role,User,Policy}Tags and Get{Role,User,Policy}, RDS ListTagsForResource and DescribeDBInstances `TagList`, Route53 ListTagsForResource, ListTagsOfResource, and DescribeCluster `tags` / EKS ListTagsForResource.
- **The tag mutations land**: TagQueue/UntagQueue, Tag/Untag{Role,User,Policy}, AddTagsToResource/RemoveTagsFromResource, ChangeTagsForResource (adds and removes in one transaction), and DynamoDB and EKS TagResource/UntagResource. Each changes only the keys it names. The SQS, RDS and Route53 tag calls were stubs that accepted and dropped tags, and listed none.
- **An unknown resource answers with the service's not-found shape**: SQS 400 `AWS.SimpleQueueService.NonExistentQueue`, IAM 404 `NoSuchEntity`, RDS 404 `DBInstanceNotFound` / `DBParameterGroupNotFound` / `DBSubnetGroupNotFoundFault`, Route53 404 `NoSuchHostedZone`, DynamoDB 400 `ResourceNotFoundException`, EKS 404 `NotFoundException`. An RDS ARN of another resource type answers 400 `InvalidParameterValue`, and a Route53 resource type other than `hostedzone` 400 `InvalidInput`.
- New `repository/tags.go` table `resource_tags`, keyed by ARN and in the reset tables. A trigger on each taggable table drops a resource's tags with its row, so a resource recreated under the same ARN starts untagged. The RDS instance's unread `tags` JSON field is gone.
- New `examples/working/tags_every_service` (provider `default_tags` plus one tagged resource per service) and `examples/updates/update_tags_every_service` (v1→v2 changes, removes and adds a tag). `coverage_matrix.yaml`'s `aws_dynamodb_table`, `aws_eks_cluster` and `aws_route53_zone` rows name the latter instead of `updates_exempt`.

### Added (EC2 tags, 2026-09-28)
- **Tags round-trip on VPCs, subnets, internet gateways, route tables, security groups and instances.** `TagSpecification.N` is stored on CreateVpc, CreateSubnet, CreateInternetGateway, CreateRouteTable, CreateSecurityGroup and RunInstances (`instance` and `network-interface`; the `volume` spec the provider adds with `default_tags` is accepted and dropped, as fakeaws has no volumes). A spec for any other resource type answers 400 `InvalidParameterValue` and creates nothing. Each Describe* returns the resource's tags as `tagSet`.
- **CreateTags and DeleteTags land** (they were the 404 default arm). DeleteTags removes a `Tag.N` by key, or by key and value when `Value` is sent, and every tag when no `Tag.N` is sent. An unknown id answers 400 with its type's code (`InvalidVpcID.NotFound`, `InvalidSubnetID.NotFound`, `InvalidInternetGatewayID.NotFound`, `InvalidRouteTableID.NotFound`, `InvalidGroup.NotFound`, `InvalidInstanceID.NotFound`, `InvalidNetworkInterfaceID.NotFound`) and changes nothing; an id of a type fakeaws does not tag answers `InvalidID`.
