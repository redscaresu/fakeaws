### Changed (security group rules are rows with sgr- ids, 2026-10-13)
- **Each rule source is an `ec2_security_group_rules` row** with its own `sgr-` id, its group, owner, direction, protocol, ports, one source (`cidr_ipv4`, `cidr_ipv6`, `prefix_list_id`, or `referenced_group_id` with `referenced_user_id`) and description, and `perm_ord`/`src_ord`, the permission's position in its direction and the source's in its permission. `ec2_security_groups` loses its `ingress` and `egress` JSON columns, so `dbSchemaVersion` is 6 and a file at 5 is refused. A group's rules and their tags go with it (`DeleteSecurityGroup`, `DeleteVpc`); a rule that references a deleted group stays.
- **`AuthorizeSecurityGroup{Ingress,Egress}` answers `return` and `securityGroupRuleSet`**, an item per rule it added, in the shape of `testdata/ec2/AuthorizeSecurityGroupIngress.xml`. A request that adds nothing (every source already held) answers `requestId` alone, as before. A permission with no source is refused 501 `NotImplemented`; it was stored as a permission with no source. A source item without its key (a `Groups.N` with a `GroupName` or `UserId` but no `GroupId`, an `IpRanges.N` with only a `Description`) is refused 501 naming its params; it was dropped silently. Any `TagSpecification.N` on Authorize is refused 501 `NotImplemented` naming `TagSpecification.N`: AWS tags the new rules, fakeaws tags none on create.
- **A `RevokeSecurityGroup{Ingress,Egress}` that names no source is refused 501 `NotImplemented`**: by `SecurityGroupRuleId.N`, with no `IpPermissions.N` (the legacy top-level form), with a permission that has no source, or with a source item without its key. Each deleted nothing and answered 200.
- `DescribeSecurityGroups` and `/mock/state` answer `ipPermissions` byte for byte as before, a permission keeping its place when a revoke removes its first source (`handlers/testdata/sg_rules_from_main.golden`).

### Added (route tables load with their main association, 2026-10-13)
- **`POST /mock/load` loads `DescribeRouteTables`** (`handlers/load_ec2_routes.go`): each route table with its tags, its routes under their recorded `origin` and `state` (the local route as recorded), and its associations under their recorded `rtbassoc-` ids. A main association has `main=true` and no subnet: `ec2_route_table_associations.subnet_id` is nullable, it gains `main`, `state`, a nullable `gateway_id` (an edge association's gateway, also with no subnet) and the route table's `vpc_id`, and the partial unique index `ec2_route_table_associations_one_main` allows one main association per VPC; `ec2_routes` gains `origin` and `state`. `dbSchemaVersion` is 5, so a file at 4 is refused. The load refuses a route table whose VPC, or an association whose subnet, no exchange loaded, a second main association of one VPC (naming the VPC), and a route with no `destinationCidrBlock` (IPv6 or prefix list). A route's `igw-` `gatewayId` references its internet gateway, refused when no exchange loaded it, unless the route is `blackhole` (AWS keeps the route of a deleted gateway), which names it under the answer's `unresolved`; `local` references nothing. Its `natGatewayId`, `instanceId`, `networkInterfaceId` and any other `gatewayId` (`vgw-`, `vpce-`, ... as `gateway`) are named under `unresolved`, as no loader loads those rows yet. An edge association's `gatewayId` references its gateway the same way (an `igw-` must be loaded, any other is named `gateway`). A recorded `propagatingVgwSet` item is refused by the rendering diff: fakeaws does not hold it.
- **`DescribeRouteTables` answers each association's `main`**, and `associationState` only when it has one (a created association's is `associated`); a main association has no `subnetId`, and an edge association answers its `gatewayId`. `association.main` matches each association's value, so `true` selects a loaded main route table and `false` a table with a subnet association (it answered `false` for every table with an association). Routes answer their stored `origin` and `state` (CreateRoute stores `CreateRoute` and `active`, which it answered before). CreateVpc still makes no main route table.
- **`DisassociateRouteTable` on a main association is 400 `InvalidParameterValue`** and the association stays, and **`DeleteRouteTable` on a main route table is 400 `DependencyViolation`**, the table and its main association staying (both UNVERIFIED: from the EC2 API reference's error list, not a recording).
- **`/mock/state` names each association's `main`, `state` and `gateway_id` and each route's `origin` and `state`**, so a main association no longer reads as one with an empty `subnet_id`. DescribeRouteTables and the loader's render share one encoder, `ec2RouteTableToXML`. `TestLoadEC2Routes_*`, `TestMainRouteTableAssociation`, `TestEC2_CreatedRouteAnswersOriginAndState` and the `not main` case of `TestEC2_DescribeRouteTablesFilters` pin it.

### Changed (IAM error codes and policy document encoding, 2026-10-12)
- **Every IAM error goes through one writer, `iamWriteError` (`handlers/iam.go`)**, which answers IAM's own codes: a missing entity is 404 `NoSuchEntity` (it was `ResourceNotFoundException`, which terraform-provider-aws does not read as gone), an entity still in use is 409 `DeleteConflict` (`DeletePolicy` on an attached policy answered `ResourceInUseException`), a duplicate create is 409 `EntityAlreadyExists` (was `ConflictException`), a second role for an instance profile is 409 `LimitExceeded`, `Cannot exceed quota for InstanceSessionsPerInstanceProfile: 1` (was `ConflictException`), and a missing required name or a malformed request is 400 `ValidationError` (was 409 `ConflictException`). An unknown action keeps 404 `ResourceNotFoundException`, marked `not-modelled-404`, so it is never read as an entity being gone. `TestRegressionIAMOneErrorWriter` pins that no other function in `handlers/iam.go` writes an error; `TestRegressionIAMMissingRoleIsNoSuchEntity`, `TestRegressionDistinct409Sentinels` and `TestRegressionIAMSecondRoleForInstanceProfileIsLimitExceeded` pin the codes.
- **IAM error messages are IAM's, naming the entity, and never an error's text**: `The role with name X cannot be found.`, `Role with name X already exists.`, `Cannot delete entity, must first remove everything attached to the role with name X.`; a call on a child of a missing parent names the parent (`iamChildEntity`). A duplicate `Create*` answered SQLite's `UNIQUE constraint failed: iam_roles.account_id, ...`, and any other failure its own text; a failure with no IAM code is now 500 `InternalFailure`, `An internal error occurred.`, with the error logged. `TestRegressionIAMDuplicateCreateMessageCarriesNoSQL` and `TestIAM_UnreadableIdentityIs500` pin it.
- **`DeleteRole` refuses with 409 `DeleteConflict` while a managed policy is attached**, as IAM does, and the role and its attachments stay (it cascaded the attachments away). The refusal is the delete's own `NOT EXISTS`, so `role_policy_attachments`' foreign key and `dbSchemaVersion` are unchanged. `TestRegressionIAMDeleteRoleWithManagedPolicyIsDeleteConflict` and `TestDeleteRoleRefusedWhileManagedPolicyAttached` pin it.
- **`DeleteUser` refuses with 409 `DeleteConflict` while an access key, an inline policy or a managed-policy attachment remains**, as IAM does (it cascaded them away), the same way. `TestRegressionIAMDeleteUserHoldingKeyIsDeleteConflict` and `TestDeleteUserRefusedWhileHeld` pin it.
- **`DeletePolicy` refuses with 409 `DeleteConflict` while the policy is attached to a user**, not only to a role (it deleted the policy and left the user's attachment dangling), and it can no longer race an attach: the delete carries both checks as `NOT EXISTS`, and `AttachRolePolicy` and `AttachUserPolicy` insert only `WHERE EXISTS` the policy, each in one statement (each checked, then wrote). `TestRegressionIAMDeletePolicyAttachedToUserIsDeleteConflict` and `TestDeletePolicyRacingAttachLeavesNoDanglingAttachment` pin it.
- **`GetUserPolicy` and `GetPolicyVersion` send the policy document URL-encoded** (`urlEscapeIfNotEmpty`, as `GetRolePolicy` and `GetRole` already did); they sent it as stored, so the provider's `url.QueryUnescape` turned a `+` into a space and a `%XX` into a byte. `TestIAM_PolicyDocumentsURLEncoded` pins a document with `%`, `+`, spaces and non-ASCII coming back byte-exact.

### Changed (EC2 Describe fidelity fixes, 2026-10-12)
- **`DescribeRouteTables` answers 500 when its route or association read fails**: it dropped both errors and answered 200 with route tables missing their routes and associations. Now EC2's `InternalFailure`, never a `routeTableSet`. `TestRegressionDescribeRouteTablesUnreadableRowsIs500` pins it.
- **An unknown `SubnetId.N` is 400 `InvalidSubnetID.NotFound`**, `The subnet ID '<id>' does not exist`, as `VpcId.N` already was (it answered 200 with an empty `subnetSet`); a subnet of another region is unknown too. `TestRegressionDescribeSubnetsUnknownIDNotFound` pins it.
- **A Describe answers an id named twice once** (`queryIDs` in `handlers/ec2.go`): `VpcId.N`, `InternetGatewayId.N`, `RouteTableId.N`, `GroupId.N`, `AllocationId.N`, `InstanceId.N`, `ImageId.N` and `InstanceType.N` answered a repeated id once per time it was named, so `VpcId.1=VpcId.2=<id>` returned the VPC twice. `TestRegressionDescribeRepeatedIDAnswersOnce` sweeps those and the Describes that already answered once (`SubnetId.N`, `NetworkInterfaceId.N`, `KeyPairId.N`).
- **`CreateVpc` makes the VPC's default security group** (`CRITICAL[ec2-vpc-default-security-group]`): named `default`, description `default VPC security group`, stored with the VPC in one transaction (`repository.CreateVPCWithDefaultGroup`; `repository.CreateVPC`, which stored a VPC alone, is gone). So `DescribeSecurityGroups` `group-name=default` with `vpc-id` answers it: the refusal of a `group-name` matching `default` (the filter table's `rowless`) is gone, and terraform-provider-aws's `aws_vpc` read finds `default_security_group_id` (it logged a warning). The group has no rules, where AWS's allows all traffic from itself and all egress; fakeaws gives a created group no default egress either. `aws_default_security_group` still cannot apply: it reads `DescribeSecurityGroupRules`, which is not modelled (the default arm, 404). `CreateSecurityGroup` `GroupName=default` is 400 `InvalidGroup.Reserved` (the unique index made it 409 `ConflictException`), `DeleteSecurityGroup` on a default group is 400 `CannotDelete`, and `DeleteVpc` removes it with the VPC. Both codes are UNVERIFIED: they come from the EC2 API reference's error list, not a recording. An unfiltered `DescribeSecurityGroups` now lists each VPC's default group too. On a database that is not loaded, boot and `/mock/restore` give each VPC stored without a default group one (`repository.BackfillDefaultGroups`, which reads the loaded flag, lists those VPCs and inserts their groups in one transaction: a file database or snapshot written before this change), so `group-name=default` never answers such a VPC with nothing; a loaded database answers its rows. `/mock/restore` backfills its copy of the snapshot before that copy goes live: `repository.Restore` now copies the baseline to `<db>.restore`, runs the caller's prepare on it, checkpoints that copy's WAL with `PRAGMA wal_checkpoint(TRUNCATE)` (an incomplete checkpoint fails the restore), then copies its bytes into the live path as before (the live path is written, never replaced, so a symlinked `--db` or a bind-mounted single-file db keeps working) and removes the `.restore` files, so a failed backfill answers 500 with the live state as it was. `TestContract_ec2_vpc_default_security_group`, `TestEC2_DefaultGroupBackfilled`, `TestEC2_RestoreBackfillFailureKeepsLiveState`, `TestBackfillDefaultGroupsIsAtomic`, `TestRestoreWritesThroughTheLivePath` and `TestRestoreFailsUnlessCheckpointed` pin it; `TestEC2_DescribeSecurityGroupsFilters` and `TestRegressionSweepDescribeSecurityGroupsListsEveryGroup` now expect the default group, and `TestCoverage_EC2ErrorPaths` drops its refusal case.
- **`RunInstances` stores `KeyName` and `DescribeInstances` answers it as `keyName`**: it was dropped, so `key_name` read back empty. A key pair the region does not have is 400 `InvalidKeyPair.NotFound`, `The key pair '<name>' does not exist` (UNVERIFIED, as above), and nothing launches. `TestRegressionRunInstancesKeyNameRoundTrips` pins it.
- **`DescribeKeyPairs` honours `IncludePublicKey`** (501 before): `true` answers each key's `publicKey`, `false` or none leaves it out, any other value is 400 `InvalidParameterValue`. **`ImportKeyPair` stores the key text**: `PublicKeyMaterial` is a blob the SDK sends base64-encoded, and it was stored as sent, so `publicKey` would have answered base64 and `data.aws_key_pair`'s `public_key` never equalled the resource's. It is decoded now (the fingerprint is the decoded text's), and material that is not base64 is 400 `InvalidKeyPair.Format` (UNVERIFIED, as above). `TestRegressionDescribeKeyPairsIncludePublicKey` pins both through the SDK client; `TestEC2_DescribeRefusesUnreadParams` refuses `DryRun` there instead, and every test that imports a key sends base64.
- **A terminated instance answers no `subnetId` and matches no `subnet-id` or `vpc-id` filter**: both now come from the primary ENI, which terminating deletes, as `privateIpAddress` and `ipAddress` already did. `availability-zone` still matches it, from the launch subnet. `TestRegressionTerminatedInstanceMatchesNoNetworkFilter` pins it; `TestEC2_DescribeInstancesFilters`' `vpc-id` rows no longer expect it.
- **An auto-assigned public IP is never an Elastic IP's or another ENI's**, so `ip-address` selects one instance. It is derived into 192.0.2.0/24 (TEST-NET-1; it was 203.0.113.0/24, the addresses' /24, by the same one-byte hash, unchecked), and `repository.CreateInstance` and `repository.DisassociateEIP` (which gives an ENI its auto-assigned IP back) store the first IP from the derived one up, wrapping within the /24, that no other ENI in the account and region holds, in the write's transaction (`claimPublicIP`); 409 once all 256 are held. `TestRegressionInstancePublicIPNeverAnEIP` and `TestClaimPublicIPStepsPastAHeldIP` pin it.

### Changed (CreateSubnet refuses overlapping CIDRs, 2026-10-12)
- **`CreateSubnet` refuses a `CidrBlock` overlapping a subnet of the same VPC** with 400 `InvalidSubnet.Conflict`, `The CIDR '<cidr>' conflicts with another subnet`, and stores nothing (`CRITICAL[ec2-subnet-overlap-refused]`; it stored both). Overlap is `netip.Prefix.Overlaps`; subnets of another VPC never conflict. `repository.CreateSubnet` now runs the VPC lookup, the sibling check and the INSERT in one transaction, so concurrent creates of one CIDR store exactly one, and returns `repository.ErrSubnetConflict`. **The code and message are unverified**: they come from the EC2 API reference, not a recording. `TestContract_ec2_subnet_overlap_refused`, `TestCreateSubnetOverlapIsAtomic` and `examples/misconfigured/subnet_cidr_overlap` pin it.

### Added (DescribeAvailabilityZones, 2026-10-12)
- **`DescribeAvailabilityZones` answers** (it fell to `handleEC2`'s default arm, 404, so `data.aws_availability_zones` and `data.aws_availability_zone` could not plan). On a database that is not loaded it answers `<region>a`, `b` and `c` in every region, each `available`, `opt-in-not-required`, `availability-zone`, with region, group and network border group the region, and zone id `<zone>-az1`. **That a-c set is not AWS's per-region set**: us-east-1 has six zones, ap-northeast-1 has no `b`, and real zone ids look like `use1-az6`.
- **A loaded database answers its `availability_zones` rows for (account, region), never the fixed set** (`CRITICAL[ec2-az-loaded-never-fixed-set]`). A region with no rows answers an empty set classed `empty-collection`; an unreadable loaded flag answers 500. The new table (zone name, zone id, state, opt-in status, zone type, group name, network border group) is fakeaws-loader's to fill (`repository.PutAvailabilityZone`); reset empties it, snapshot/restore keep it, and an AZ row makes the database non-empty, so `POST /mock/identity` refuses an account change on it.
- **A subnet's `availabilityZoneId` comes from the same zones** (`ec2Zones` in `handlers/ec2.go`), read once per `CreateSubnet` and `DescribeSubnets`: `<zone>-az1` as before on an unloaded database; on a loaded one the stored zone id, empty for a zone with no row (it was `<zone>-az1` there too).
- **`CreateSubnet` honours `AvailabilityZoneId`** (`subnetZone` in `handlers/ec2.go`; it was ignored, so `availability_zone_id = data.aws_availability_zones.x.zone_ids[1]` placed the subnet in `<region>a` and the provider read back another zone): an id that is one of `ec2Zones`' zone ids places the subnet in that zone. Any other id, an empty one, or one that names another zone than `AvailabilityZone` is refused through `ec2Refuse`, 501 `NotImplemented` naming `AvailabilityZoneId`, and nothing is created. `TestEC2_CreateSubnetAvailabilityZoneId` pins it.
- Filters `zone-name`, `zone-id`, `state`, `region-name`, `opt-in-status`, `zone-type`, `group-name` and `network-border-group` (`zoneFilters`), `ZoneName.N` and `ZoneId.N`; a name or id that is none of the region's zones answers 400 `InvalidParameterValue` naming it (UNVERIFIED: from the EC2 API reference, no recording), except in a loaded region with no rows, which answers the empty set classed `empty-collection`. Without `AllAvailabilityZones=true` a zone whose opt-in status is `not-opted-in` is left out, as in AWS; a value other than `true` or `false` is 400 `InvalidParameterValue`. Any other param or filter is refused, 501 `NotImplemented`. `TestEC2_DescribeAvailabilityZones`, `TestContract_ec2_az_loaded_never_fixed_set`, `TestEC2_DescribeAvailabilityZonesAllAvailabilityZones`, `TestRegressionDescribeAvailabilityZonesAnswered`, `TestAvailabilityZonesLifecycle` and `TestAvailabilityZoneRowIsNotEmpty` pin it.

### Changed (KMS keys are rows, 2026-10-12)
- **KMS keys are `kms_keys` rows** (`repository/kms.go`), keyed by account, region and key id, instead of the package-global `kmsStore` map, which outlived `/mock/reset`, was left out of snapshot and restore, was invisible to the identity guard's empty check and was shared by every `Application` in a process. So `/mock/reset` deletes every key; a snapshot carries the keys and a restore brings back exactly those; and two `Application`s keep separate keys. A key counts as a row for `POST /mock/identity` and `-account`, which refuse another account naming both ids while one exists, except a key in `PendingDeletion` (`repository.KMSKeyStatePendingDeletion`, skipped by `isEmpty` in `repository/identity.go`): that is all a destroyed `aws_kms_key` leaves, and the identity is accepted after a destroy as after every other service's. `MUST[responses-carry-the-stored-account]` loses its KMS exception: a key always answers under the stored account. Keys are regional, as in AWS: a key created in one region is not found in another (it answered in every region). Each update (rotation, description, tags, `ScheduleKeyDeletion`) reads and writes the key in one transaction (`repository.UpdateKMSKey`).
- **`/mock/state` has a `kms` block**, `{"keys": [{key_id, arn, state, region, account}]}`: every key under the stored account in every region, `PendingDeletion` included. A failed read answers 500 `kms state could not be read`, like every other block.
- **A KeyId is a key id or the key's ARN** in every key operation (`kmsKeyRef` in `handlers/kms.go`); an ARN in another region or account matches no key. fakeaws stores no aliases, so `DescribeKey` refuses an alias name or alias ARN, which AWS accepts there, with 501, classed `filter-refused`; the operations AWS gives only a key id or ARN answer an alias as an unknown key.
- **An unknown key is 404 `NotFoundException`**, the code terraform-provider-aws reads as gone, in every key operation (it was `ResourceNotFoundException`). `GetKeyPolicy` now looks the key up like the others: an unknown key, one in another region and one gone after a reset are 404 (it answered the default policy for any KeyId).
- **New `ListKeys`**: every key in the request's region, `PendingDeletion` included, as `{KeyId, KeyArn}` in one page with `Truncated: false`; `Limit` and `Marker` are ignored (it was the default arm, 404 `not-modelled-404`).
- `TestKMS_ResetDeletesKeys`, `TestKMS_SnapshotRestoreCarriesKeys`, `TestKMS_ApplicationsKeepSeparateKeys`, `TestKMS_KeysAreRegional`, `TestKMS_StateListsKeys`, `TestKMS_DestroyLeavesIdentityFree` (the requests the provider sends to apply and destroy `examples/working/kms_key`, recorded with `-record-requests`), `TestKMS_GetKeyPolicyNeedsTheKey`, `TestKMS_KeyArnAccepted`, the `kms key` case of `TestContract_identity_change_refused_on_non_empty_db`, two `ListKMSKeys` cases in `stateBreaks` and a KMS case in `TestContract_request_log_filter_refused` pin it. `TestKMS_KeyKeepsItsAccount`, which pinned the exception, is gone; `TestContract_responses_carry_the_stored_account` sweeps `ListKeys` and the `kms` state block too; `TestContract_request_log_read_set_entry`'s DescribeKey by alias now records 501.

### Added (image filters, 2026-10-12)
- **`DescribeImages` honours filters**, each name defined in `imageFilters` in `handlers/ec2.go` (it refused every `Filter.N`, so `data.aws_ami`'s `filter` blocks answered 501): the fields an AMI row stores and what is derived from them, with `tag:<Key>`, `tag-key` and `tag-value`. `name`'s `*` crosses `/`, so `ubuntu/images/*` selects both Ubuntu fixtures. ### Changed (instance, network interface, address and key pair filters; DescribeInstances answers one region, 2026-10-12)
- **An unfiltered `DescribeInstances` lists the caller's region only**; it listed every region's instances, so a read in `us-east-1` returned an `eu-west-2` instance with 200. `InstanceId.N` was already region-scoped. `TestRegressionDescribeInstancesListsOneRegion` pins it.
- **`DescribeInstances` and `DescribeKeyPairs` honour filters, and `DescribeNetworkInterfaces` and `DescribeAddresses` honour more**, each name defined in one table in `handlers/ec2.go`: `instanceFilters` (was: every filter refused; `vpc-id` and `availability-zone` are the subnet's, `private-ip-address` and `ip-address` the primary ENI's, so a terminated instance matches neither), `eniFilterValues` (was: `network-interface-id`, `attachment.instance-id`, `subnet-id`, `group-id`), `addressFilters` (was: `association-id`) and `keyPairFilters` (was: every filter refused), each with `tag:<Key>`, `tag-key` and `tag-value`. A filter that matches nothing answers 200 with an empty set; every other name stays refused, 501 `NotImplemented` naming it, classed `filter-refused`.
- **`DescribeAddresses` honours `PublicIp.N` and `DescribeKeyPairs` honours `KeyPairId.N`** (both were refused, 501). An address not in the region answers 400 `InvalidAddress.NotFound`, an unknown key pair id 400 `InvalidKeyPair.NotFound`. An unknown `KeyName.N` answers the same 400 `InvalidKeyPair.NotFound` naming the key (`writeKeyPairNotFound`); it was 404 `ResourceNotFoundException` with no name, which terraform-provider-aws's `aws_key_pair` read does not take as gone, so a refresh after an out-of-band delete failed. Both codes are UNVERIFIED: they come from the EC2 API reference's error list, not a recording. `KeyName.N` now answers the key pairs sorted by name, not in request order.
- **No two Elastic IPs in an account and region share a public IP, and key pair fingerprints are distinct**, so `PublicIp.N`, `public-ip` and `fingerprint` each select one. AllocateAddress's IP is still derived from the allocation id into 203.0.113.0/24, but that hash collides (about even odds by 20 addresses); `repository.CreateEIP` now stores the first IP from the derived one up, wrapping within the /24, that no address in the region holds, in one transaction, and is `ErrConflict` (409) once all 256 are held. `ec2KeyFingerprint` repeated one hashed byte 16 times (256 values); it is now the first 16 bytes of the public key's SHA-256, same `xx:..:xx` shape. `TestCreateEIPStepsPastAHeldIP`, `TestRegressionAllocateAddressNeverSharesAPublicIP` and `TestRegressionKeyPairFingerprintSelectsOneKey` pin them. `TestRegressionSweepDescribeAddressesListsEveryAddress`'s `PublicIps` case expected the 501; it now expects the address, and the 400 for an unknown one.

### Changed (DescribeInstanceAttribute answers from rows, 2026-10-12)
- **DescribeInstanceAttribute answers each attribute fakeaws stores from the instance row** (`CRITICAL[ec2-instance-attributes-from-rows]`): `disableApiTermination`, `disableApiStop`, `instanceInitiatedShutdownBehavior` and `ebsOptimized` from the instance, `sourceDestCheck` from its primary ENI, `userData` as before. They were constants (`false`, `false`, `stop`, `false`, `true`), so a `source_dest_check = false` stored by ModifyInstanceAttribute read back `true` here. With nothing set each still answers AWS's default; a terminated instance, which has no ENI, answers no `sourceDestCheck`, as DescribeInstances does.
- **RunInstances stores `DisableApiTermination`, `DisableApiStop`, `EbsOptimized` and `InstanceInitiatedShutdownBehavior`, and ModifyInstanceAttribute stores each as `<Name>.Value`** (`ec2InstanceAttributes` in `handlers/ec2.go`; it ignored all but `SourceDestCheck.Value`). DescribeInstances answers `ebsOptimized` only when true, so a launch that sets none of them describes byte for byte as before. `disableApiStop` is stored and answered, but nothing enforces it: fakeaws has no StopInstances, which stays refused as not modelled (the default arm, `not-modelled-404`), and the contract test pins that. Each value must be one AWS accepts, `true` or `false` for the three booleans and for `SourceDestCheck.Value`, `stop` or `terminate` for the shutdown behaviour; anything else, `True` or an empty value included, is 400 `InvalidParameterValue` (UNVERIFIED: from the EC2 API reference's error list, not a recording) and nothing is created or written. A boolean read any value but `true` as false before.
- **ModifyInstanceAttribute refuses every param it does not store, and writes in one transaction.** `UserData.Value`, `InstanceType.Value`, `GroupId.N`, `BlockDeviceMapping.N.*`, the legacy `Attribute`/`Value` form and anything else outside `InstanceId`, `SourceDestCheck.Value` and the `ec2InstanceAttributes` names is refused (it answered 200 and dropped them): 501 `NotImplemented`, `ModifyInstanceAttribute: not modelled by fakeaws: <names>`, classed `filter-refused`, before anything is written. A request with no attribute is 400 `MissingParameter` (it answered 200), and writes nothing. The ENI's `sourceDestCheck` and the instance's attributes commit in one transaction (`repository.UpdateInstanceAttributes`), so a failure applies neither; it reads the instance in the same transaction, so a terminate cannot land between the read and the write and be undone. A terminated instance is refused for every attribute with 400 `IncorrectInstanceState` (`SourceDestCheck` was 409, the others were stored), and an unknown instance is 400 `InvalidInstanceID.NotFound` (was 404 `ResourceNotFoundException`). `IncorrectInstanceState` and `MissingParameter` are UNVERIFIED: they come from the EC2 API reference's error list, not a recording. `ec2RefuseUnread` and the Describe filter evaluator's `read` share one `unread` (`handlers/ec2_filters.go`), which keeps the refusal of a key with a literal `N` segment.
